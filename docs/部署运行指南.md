## 1. 环境要求

| 项目 | 要求 |
|------|------|
| 操作系统 | Linux（CentOS 7+ / RHEL 7+ / Ubuntu 18.04+） |
| Docker | 已安装并运行（`docker info` 正常） |
| expect | `yum install -y expect` 或 `apt-get install -y expect` |
| Python | 3.6.8+（`python3 --version`，CentOS 7 使用 `python36`） |
| C++ 编译环境 | `gcc-c++ python3-devel`（CentOS）或 `g++ python3-dev`（Ubuntu），QuickFIX 编译需要 |
| 磁盘空间 | ≥ 20GB（三个镜像约 5-10GB） |
| 网络 | 宿主机有可用 IP，容器间可互通 |

## 3. 快速开始

```bash
# === 第一步：部署 Docker 环境 ===

# Step 1: 上传文件到 Docker 宿主机
scp -r scripts/ root@<宿主机IP>:/opt/fix-test/

# Step 2: 登录宿主机，一键部署
ssh root@<宿主机IP>

# Step 3: 一键部署完成（含环境 + 镜像构建 + 测试执行）

# 查看部署日志
ls -t scripts/logs/env_setup_*.log | head -1 | xargs cat

# === 第二步：查看测试报告 ===
# 报告输出在 scripts/logs/reports/
ls scripts/logs/reports/
# test_report.html  test_report.json  syslog.txt  report.log
```

## 4. 分步详解

### 4.1 上传文件

将 `scripts/` 整个目录及三个 `.tar` 镜像文件复制到 Docker 宿主机：

```bash
# 在本地执行
cd /path/to/FixDockerAutoTest
scp -r scripts/ root@192.168.1.100:/opt/fix-test/
scp exchangeFIX.tar CtpTradeFIX.tar FIX.tar root@192.168.1.100:/opt/fix-test/scripts/
```

### 4.2 检查前置条件

```bash
# 确认 Docker 运行
docker info

# 确认 expect 已安装
which expect

# 确认 tar 文件存在
ls -lh /opt/fix-test/scripts/*.tar

# 确认脚本可执行
ls -l /opt/fix-test/scripts/*.sh
```

### 4.3 执行部署

```bash
cd /opt/fix-test/scripts
bash env_setup.sh
```

部署过程分为 3 个阶段，预计耗时 5-15 分钟：

```
阶段 1/3：交易所容器
  ├── 导入镜像 exchangeFIX.tar → exchangefix:v1
  ├── 创建容器 exchangefix（端口 26171, 26181）
  ├── 配置 SSH 密钥
  ├── setcap ping 权限
  ├── 修改 service.list（IP → 容器自身 IP）
  ├── 修改 DeployConfig.xml（IP + 组播地址）
  └── 启动交易所服务（ecall.sh → confirmMainBackup.sh）

阶段 2/3：CTP 交易柜台容器
  ├── 导入镜像 CtpTradeFIX.tar → ctptradefix:v2
  ├── 创建容器 ctptradefix（端口 11157, 11167, 11155）
  ├── 配置 SSH 密钥
  ├── 修改 /etc/hosts（添加 30+ 主机别名）
  ├── 修改 4 个 INI 文件 + GenMD5.sh
  │   ├── ineoffer.ini    (ExchangeAddress → 交易所IP)
  │   ├── inemdserver.ini (FrontAddr → 交易所IP)
  │   ├── shfeoffer.ini   (ExchangeAddress → 交易所IP)
  │   └── shfemdserver.ini(FrontAddr → 交易所IP)
  ├── 修改 DeployConfig.xml（组播地址）+ cpall.sh
  └── 启动 CTP 服务（startall.sh）

阶段 3/3：FIX 网关容器
  ├── 导入镜像 FIX.tar → ctpfix:v1
  ├── 创建容器 ctpfix（端口 50001, 61111）
  ├── setcap ping 权限
  ├── 修改 fixfront_mt.ini (CTPfront1 → CTP容器IP) + GenMD5.sh
  ├── 修改 fixfront_md.ini (MDfront1 → CTP容器IP) + GenMD5.sh
  └── 启动 FIX 网关服务（startall.sh）
```

### 4.4 验证部署

```bash
# 检查三个容器都在运行
docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'

# 预期输出：
# NAMES         STATUS          PORTS
# ctpfix        Up XX minutes   0.0.0.0:50001->50001/tcp, 0.0.0.0:61111->61111/tcp
# ctptradefix   Up XX minutes   0.0.0.0:11155->11155/tcp, 0.0.0.0:11157->11157/tcp, 0.0.0.0:11167->11167/tcp
# exchangefix   Up XX minutes   0.0.0.0:26171->26171/tcp, 0.0.0.0:26181->26181/tcp

# 检查 FIX 端口可达
nc -zv localhost 61111
# 预期：Connection to localhost 61111 port [tcp/*] succeeded!
```

### 4.5 查看容器 IP

部署完成后脚本会打印各容器 IP。也可手动查询：

```bash
docker inspect -f '{{.Name}} → {{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' \
    exchangefix ctptradefix ctpfix
```

## 5. 脚本说明

### 5.1 `common.sh` — 公共函数库

被所有脚本引用（`source`），提供：

| 函数/变量 | 说明 |
|-----------|------|
| `detect_host_ip()` | 自动检测宿主机 IP |
| `get_container_ip(name)` | 获取容器在 Docker 网络上的 IP |
| `get_broadcast_ip(ip)` | 基于 IP 计算 /24 子网广播地址 |
| `container_exists(name)` | 判断容器是否存在 |
| `image_exists(name)` | 判断镜像是否存在 |
| `network_exists(name)` | 判断 Docker 网络是否存在 |
| `log_info/error/success/step` | 带时间戳和颜色的日志输出 |

### 5.2 `env_setup.sh` — 主编排器

**用法：**
```bash
bash env_setup.sh
```

**功能：**
- 检查前置条件（Docker、expect、tar 文件）
- 创建 Docker 桥接网络 `fix-test-net`
- 按顺序调用三个阶段脚本
- 每个阶段完成后获取容器 IP 传递给下一阶段
- 打印部署摘要

### 5.3 `setup_exchange.sh` — 交易所容器

**镜像：** `exchangeFIX.tar` → `exchangefix:v1`
**容器：** `exchangefix`，端口 26171/26181
**用户：** trade2
**修改的配置文件：**
- `/home/trade2/shell/console/service.list`
- `/home/trade2/cfg/config/DeployConfig.xml`

### 5.4 `setup_ctptrade.sh` — CTP 交易柜台

**镜像：** `CtpTradeFIX.tar` → `ctptradefix:v2`
**容器：** `ctptradefix`，端口 11157/11167/11155
**用户：** trade1
**修改的配置文件：**
- `/etc/hosts`
- `~/ineoffer2/bin/ineoffer.ini`
- `~/inemdserver2/bin/inemdserver.ini`
- `~/shfeoffer1/bin/shfeoffer.ini`
- `~/shfemdserver1/bin/shfemdserver.ini`
- `/home/trade1/cfg/config/DeployConfig.xml`

### 5.5 `setup_fixgateway.sh` — FIX 网关

**镜像：** `FIX.tar` → `ctpfix:v1`
**容器：** `ctpfix`，端口 50001/61111
**用户：** fixf1
**修改的配置文件：**
- `/home/fixf1/fixfront_mt1/bin/fixfront_mt.ini`
- `/home/fixf1/fixfront_md1/bin/fixfront_md.ini`

### 5.6 `cleanup.sh` — 环境清理

**用法：**
```bash
bash cleanup.sh           # 仅清理容器和网络
bash cleanup.sh --images  # 同时删除 Docker 镜像
```

**清理顺序：** ctpfix → ctptradefix → exchangefix（逆依赖顺序）

## 7. 故障排查

### 7.1 容器启动失败

```bash
# 查看容器日志
docker logs exchangefix
docker logs ctptradefix
docker logs ctpfix

# 检查镜像是否存在
docker images | grep -E 'exchangefix|ctptradefix|ctpfix'
```

### 7.2 SSH 服务未启动

如果 `docker exec` 进入容器失败，说明 sshd 未正常运行：

```bash
# 手动启动（如果容器在运行但 sshd 挂了）
docker exec exchangefix /usr/sbin/sshd -D &
```

### 7.3 容器间网络不通

```bash
# 验证容器在同一网络
docker network inspect fix-test-net

# 从 FIX 网关 ping CTP 容器
docker exec ctpfix ping -c 3 $(docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' ctptradefix)
```

### 7.4 端口被占用

```bash
# 检查端口占用
ss -tlnp | grep -E '61111|50001|11157|11167|11155|26171|26181'

# 如果端口被占用，修改 docker run 的端口映射
# 编辑对应 setup_*.sh 中的 -p 参数
```

### 7.5 幂等性——重新部署

所有脚本支持重复执行（幂等）。如果需要完全重新部署：

```bash
# 方式 1：清理后重新部署
bash cleanup.sh --images
bash env_setup.sh

# 方式 2：直接重新运行（脚本会跳过已存在的步骤）
bash env_setup.sh
```

### 7.6 setcap 失败

如果看到 `setcap may have failed` 警告，这通常不影响核心功能（仅影响容器内 ping 命令）。如果需要修复：

```bash
# 在宿主机上给容器特权
docker exec --privileged exchangefix setcap cap_net_raw+ep /usr/bin/ping
```

### 7.7 GenMD5.sh 执行失败

检查 INI 文件路径是否正确：

```bash
# 在 CTP 容器内验证
docker exec ctptradefix ls -la /home/trade1/ineoffer2/bin/ineoffer.ini
docker exec ctptradefix ls -la /home/trade1/inemdserver2/bin/inemdserver.ini
docker exec ctptradefix ls -la /home/trade1/shfeoffer1/bin/shfeoffer.ini
docker exec ctptradefix ls -la /home/trade1/shfemdserver1/bin/shfemdserver.ini

# 在 FIX 容器内验证
docker exec ctpfix ls -la /home/fixf1/fixfront_mt1/bin/fixfront_mt.ini
docker exec ctpfix ls -la /home/fixf1/fixfront_md1/bin/fixfront_md.ini
```

### 7.8 startall.sh 或 ecall.sh 未找到

这些脚本应该在对应用户的 PATH 中。如果找不到：

```bash
# 尝试使用完整路径
docker exec exchangefix su - trade2 -c "which ecall.sh"
docker exec ctptradefix su - trade1 -c "which startall.sh"
docker exec ctpfix su - fixf1 -c "which startall.sh"
```

## 9. 运行测试

### 9.1 前置条件

- Docker 测试环境已通过 `env_setup.sh` 部署完成
- 三个容器均正常运行（`docker ps` 确认）
- Python 3.7+（`python3 --version` 确认）
- （仅 Linux）C++ 编译环境（QuickFIX 需从源码编译）

### 9.2 安装依赖

```bash
cd FixAutoTest/FixAutoTest

# ===== Linux =====
# 1. 安装编译环境（首次）
# CentOS/RHEL:
sudo yum install -y gcc-c++ python3-devel
# Ubuntu/Debian:
sudo apt-get install -y g++ python3-dev

# 2. 安装 Python 依赖
pip3 install -r requirements.txt

# ===== Windows =====
# 可使用自带的预编译 wheel（无需编译环境）
pip3 install softpackage/quickfix-1.15.1-cp37-cp37m-win_amd64.whl
pip3 install softpackage/xlrd-1.2.0-py2.py3-none-any.whl
```

> **说明：** 如果使用 YAML 格式用例（`caselist.txt` 中引用 `.yaml` 文件），需要安装 `PyYAML`：`pip3 install PyYAML>=5.1`。离线环境请使用 §9.2.1 的离线安装方案。

#### 9.2.1 离线环境安装

目标机器无法联网时，需要先在**联网 Linux 机器**上准备离线包。分两种情况：

**情况 A：PyPI 有预编译包（优先尝试）**

```bash
# 在联网 Linux 机器上运行（需和目标机器 Python 版本一致）
cd FixDockerAutoTest/scripts
bash download_offline_deps.sh 3.6    # 指定 Python 版本

# 如果成功: 产出 softpackage/offline-linux-py36.tar.gz
# 复制到目标机器安装即可
```

**情况 B：无预编译包 → 本地编译（--build 模式）**

当 PyPI 没有对应 manylinux wheel 时（常见于 Python 3.6），在联网机器上编译：

```bash
# 1. 联网机器安装编译环境（一次性）
yum install -y python36-devel gcc-c++

# 2. 编译 quickfix 为 wheel
bash download_offline_deps.sh 3.6 --build

# 3. 产出 softpackage/offline-linux-py36.tar.gz
#    (内含本机编译的 .whl，复制到目标机器直接安装，无需编译)
```

**安装阶段（离线目标机器）：**

```bash
# 方式 A: 一键安装脚本
cd FixDockerAutoTest/scripts
bash install_offline.sh

# 方式 B: 手动安装
cd FixAutoTest/FixAutoTest
tar xzf softpackage/offline-linux-py36.tar.gz -C /tmp/fix-pkgs/
pip3 install --no-index --find-links=/tmp/fix-pkgs/ quickfix xlrd
```

#### 9.2.2 验证安装

```bash
# 一键验证（install_offline.sh 安装后自动执行）
bash scripts/install_offline.sh

# 手动验证
python3 -c "import quickfix"                                 # 无报错即正常（v1.15 无 __version__）
python3 -c "import _quickfix"                                # C++ 扩展，无报错即正常
python3 -c "import xlrd; print(xlrd.__VERSION__)"           # 应输出版本号
```

> **注意：**
> - 情况 A 的包是 PyPI 预编译 manylinux wheel，无需 gcc/python-devel
> - 情况 B 的包是本机编译的，**仅适用于相同 OS 和 Python 版本**的目标机器
> - 用 `--build` 编译时，目标机器**不需要** python-devel 和 gcc
> - xlrd 是纯 Python，无需编译

### 9.3 Linux vs Windows 差异速查

| 项目 | Linux | Windows |
|------|-------|---------|
| Python 版本 | 3.6.8+ (CentOS 7 默认 `python36`) | 3.7+ |
| Python 命令 | `python3` 或 `python3.6` | `python` |
| QuickFIX 安装 | **联网:** `pip3 install quickfix`（manylinux wheel）| 自带 `softpackage/*.whl` 直接安装 |
|  | **离线:** `bash scripts/install_offline.sh`（预编译包）| 同，直接用 wheel |
| 编译环境 | 在线需要；离线预编译包**不需要** | 不需要 |
| 路径分隔符 | `/` | `\`（代码已用 `os.path` 适配） |
| 编码 | `utf-8`（原生） | `utf-8`（已从 `raw_unicode_escape` 改为 `utf-8`） |
| 启动方式 | `FIX_HOST=IP python3 FixInitiator.py` | `set FIX_HOST=IP` 或 `bash launcher.sh` |

### 9.4 启动方式

**方式 A：使用 launcher.sh（推荐，支持环境变量）**

```bash
# 指定 FIX 网关地址（Docker 宿主机 IP）
export FIX_HOST=192.168.1.100
bash launcher.sh

# 一行命令
FIX_HOST=192.168.1.100 bash launcher.sh
```

**方式 B：直接使用 Python + CLI 参数（重构后新增）**

```bash
# 运行 caselist.txt 中全部用例，指定 FIX 网关地址
python3 FixInitiator.py --host 192.168.1.100

# 运行单个测试用例
python3 FixInitiator.py --host 192.168.1.100 --config FIX42-01.ini --case testcase/orderinsert-00001-1.xlsx

# 指定自定义 caselist
python3 FixInitiator.py --host 192.168.1.100 --caselist my_caselist.txt

# 首次连接新网关时，重置序列号
python3 FixInitiator.py --host 192.168.1.100 --reset-seqnums
```

**方式 C：环境变量方式**

```bash
export FIX_HOST=192.168.1.100
python3 FixInitiator.py
```

### 9.5 CLI 参数完整说明

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `--host` / `FIX_HOST` 环境变量 | FIX 网关地址（覆盖 INI 文件中的 `SocketConnectHost`） | INI 文件中的值 |
| `--port` / `FIX_PORT` 环境变量 | FIX 网关端口 | `61111` |
| `--config` | 单个测试的 QuickFIX 配置文件 | — |
| `--case` | 单个测试用例 Excel 文件路径 | — |
| `--caselist` | 批量测试的用例列表文件 | `caselist.txt` |
| `--reset-seqnums` | 启动前清除序列号文件（首次连接新网关时必须使用） | 不重置 |

> **注意：** `--config` 和 `--case` 必须同时使用（运行单个用例）。不指定时默认读取 `caselist.txt` 批量运行。

### 9.6 典型 Docker 环境完整流程

```bash
# 1. 确认容器都在运行
docker ps | grep -E 'exchangefix|ctptradefix|ctpfix'

# 3. 进入测试目录
```

## 11. 容器化测试运行器

### 11.1 概述

`fix-runner` 将 FixAutoTest 打包为 Docker 镜像，内置 Python + quickfix + xlrd，无需在宿主机安装任何依赖。`env_setup.sh` 阶段 4 自动处理。

### 11.2 自动运行（推荐）

```bash
# env_setup.sh 部署完成后自动执行阶段4：
#   构建 fix-runner 镜像 → 运行容器 → 输出报告到 scripts/logs/reports/
bash env_setup.sh

# 跳过阶段4（仅部署环境，稍后手动测试）
SKIP_RUNNER=true bash env_setup.sh
```

### 11.3 手动运行

```bash
# 环境已就绪，单独运行测试
bash scripts/setup_runner.sh --host 192.168.56.101

# 仅构建镜像
bash scripts/setup_runner.sh --build-only

# 仅运行已有镜像
bash scripts/setup_runner.sh --run-only --host 192.168.56.101
```

### 11.4 离线导出/导入

在已部署好的服务器上打包镜像：

```bash
# 服务器 A：打包镜像（自动检测网络，离线回退到容器 commit）
bash scripts/export_runner_image.sh
# → 产出: FixAutoTest/FixAutoTest/softpackage/fix-runner.tar
```

将 `fix-runner.tar` 复制到离线目标机器：

```bash
# 目标机器：导入镜像
docker load -i /opt/fix-test/scripts/../FixAutoTest/FixAutoTest/softpackage/fix-runner.tar

# 运行测试
bash scripts/setup_runner.sh --run-only --host 192.168.56.101
```

### 11.5 执行方式对比

| 方式 | 依赖 | 适用场景 |
|------|------|---------|
| `env_setup.sh`（阶段4） | Docker + 网络或预构建 tar | 一键部署+测试 |
| `setup_runner.sh` | Docker + fix-runner 镜像 | 环境已部署，单独跑测试 |
| `export_runner_image.sh` | 已部署的服务器 | 制作离线包迁移到无网络机器 |
| 直接 `python3 FixInitiator.py` | Python3 + quickfix + xlrd | 开发调试 |
